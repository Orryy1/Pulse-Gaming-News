# Pulse Gaming Long-form Operations

## Purpose

Pulse long-form is a governed production lane, not an extension of the Shorts assembler. It turns verified stories into original, chaptered programmes with exact-subject motion, clear player utility and independent quality evidence.

No long-form format is publishable merely because its script or MP4 exists. The source, transcript, motion, render, revenue and operator-review gates must agree.

## Recurring formats

| Format | Cadence | Target | Primary value |
| --- | --- | --- | --- |
| Weekly News Verdict | Weekly | 10-18 minutes | What mattered and what changes for players |
| Monthly Release Radar | Monthly | 12-22 minutes | Ranked, dated release decisions |
| Ranked Countdown | Fortnightly or event-led | 12-26 minutes | Original Pulse ranking and trade-offs |
| Single-Topic Deep Dive | Twice monthly or event-led | 15-35 minutes | Original investigation and material payoff |
| Source-Backed Launch Verdict | Launch-led | 10-22 minutes | Buy, wait or skip using attributable evidence |
| Buyer Guide | Monthly, seasonal or price-led | 12-30 minutes | Transparent use-case recommendations |

The machine-readable contract is generated by:

```powershell
npm run longform:portfolio -- --json
```

## Production flow

```text
official and reliable discovery
  -> governed source and claim manifests
  -> long-form candidate intake and dedupe
  -> format-specific editorial thesis
  -> chapter and exact-subject motion plan
  -> original narration and word timestamps
  -> 1080p long-form render
  -> transcript, freeze, black-frame, motion and bitrate QA
  -> revenue and disclosure pack
  -> operator review
  -> separately authorised publish decision
```

## Operator commands

Generate the current portfolio:

```powershell
npm run longform:portfolio -- --json
```

Build a read-only candidate intake from the current governed queue:

```powershell
npm run ops:longform-candidate-intake -- --target-month 2026-08 --json
```

Multiple governed inputs can be combined without mutating the database:

```powershell
npm run ops:longform-candidate-intake -- --target-month 2026-08 `
  --input output/candidate-supply/fresh_candidate_queue.json `
  --input data/release-radar/august-2026-research-a.json `
  --input data/release-radar/august-2026-research-b.json
```

Generate a Pulse Release Radar package after ten candidates pass:

```powershell
npm run format:pulse-release-radar -- --month "August 2026" --json
```

Rendering remains blocked unless the package has ten complete candidates, a ten-minute minimum estimated runtime and passing transcript QA:

```powershell
npm run format:pulse-release-radar -- --month "August 2026" --render-longform --json
```

Check the existing weekly build and aggregate long-form operations:

```powershell
npm run ops:weekly-longform-readiness -- --json
npm run ops:longform-operations -- --json
```

## Required evidence

Every chapter requires:

- a canonical subject and public title
- a primary official or reliable source URL
- sourced confirmed claims and no prohibited claims
- a concrete player consequence
- a story-specific curiosity gap and payoff
- exact-subject official or licensed motion
- a rights basis for every visual and audio asset
- original Pulse analysis rather than article recitation

The weekly lane additionally requires at least eight fresh chapters and a source age of no more than seven days. The release radar requires at least ten games with official release-date and platform evidence.

## Quality contract

A production episode must have:

- at least 600 seconds of final runtime
- at least 1,200 words for the legacy minimum, with format-specific targets normally higher
- complete chapter timestamps
- at least 1.5 Mbps video bitrate, with production targets materially above that floor
- exact-subject motion for every major chapter
- no repeated generic gameplay bed
- no placeholder, scaffold or internal QA language
- no frozen, black, choppy or low-detail sections
- fresh narration and word timestamps
- a readable first frame, cover and chapter system

## Revenue contract

Long-form revenue is diversified rather than dependent on ads alone:

- YouTube watch-page ads and mid-roll inventory
- story-relevant Amazon UK and US affiliate links
- source-first comparison and buyer-guide landing pages
- newsletter capture
- sponsor-safe pre-roll and chapter-boundary inventory
- derivative Shorts, carousels and discussion posts that return viewers to the programme

YouTube currently allows mid-roll ads on monetised videos that are eight minutes or longer. Full ad-revenue eligibility still requires the applicable YouTube Partner Programme threshold and channel review. Shorts-feed watch hours do not count towards the 4,000 public-watch-hour route. See the official [YouTube Partner Programme overview](https://support.google.com/youtube/answer/72851?hl=en), [mid-roll guidance](https://support.google.com/youtube/answer/6175006?hl=en) and [channel monetisation policies](https://support.google.com/youtube/answer/1311392?hl=en).

Affiliate links must be relevant to the chapter, correctly tagged, region-aware and conspicuously disclosed. Commission rate must never determine editorial ranking.

## Publish boundary

The tools in this lane default to local proof and operator review. They do not grant publish permission.

Long-form upload requires all of the following:

- a passing final quality report
- an explicit format-specific auto-publish flag
- the general long-form and platform publish flags
- an explicit operator-confirmed invocation

The healthy Shorts and Reels scheduler remains independent. A blocked long-form episode must not hold or weaken the enabled short-form platforms.
